# Test Harness Expansion

## Summary

Commits `c0e547a`, `d4588f3`, `49d036c`, and `74e0180` mark a large step up in automated test infrastructure:

- add explicit test hooks
- add core unit tests
- expand MainApp-facing test access
- add a Linux rebuild-and-test helper script

## Motivation

As the app grew beyond a simple UI wrapper, it needed better seams for testing local-LLM behavior, filesystem logic, and main-window flows. Without those seams, every new runtime change would keep leaning on manual testing.

## Implementation

This sequence introduced:

- `TestHooks` infrastructure
- dedicated test access helpers such as `LocalLLMTestAccess`
- broader test targets in `app/CMakeLists.txt`
- helper scripts that made repeatable Linux rebuild/test cycles easier

## Validation

The purpose of this cluster was validation itself: it created the infrastructure later commits could use to prove behavior instead of merely describing it.

## User-visible impact

There is no direct UI feature here, but this work materially improved the project’s ability to ship later behavior changes with real automated coverage.

## Remaining caveats

Even after this expansion, some GPU/runtime/platform issues still required smoke testing on real machines. The test harness reduced that gap but did not eliminate it.
