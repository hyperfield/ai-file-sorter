# AI File Sorter — Application Code

> Parent: [../AGENTS.md](../AGENTS.md)

Application source code for the AI File Sorter desktop app. C++20 with Qt6, compiled into `bin/aifilesorter` on Linux/macOS or a bundled Windows package via `build_windows.ps1`.

## Structure

```
app/
├── main.cpp                  # QApplication entry point; CLI parsing, dev/test mode, single-instance check
├── startapp_linux.cpp        # Linux launcher backend selection (CUDA → Vulkan → CPU)
├── startapp_windows.cpp      # Windows launcher and updater handoff
├── lib/*.cpp                 # ~80 implementation modules (services, dialogs, analyzers, clients)
├── include/*.hpp             # One header per implementation module, plus test-access shims
├── include/external/llama.cpp # Tracked submodule — read-only
├── include/llama/llama.h     # Minimal wrapper around llama.cpp headers
├── CMakeLists.txt            # Canonical cross-platform build
├── Makefile                  # Linux/macOS day-to-day build
├── scripts/                  # Build, packaging, and diagnostics helpers
├── resources/                # Qt .qrc, translations, icons, help, certificates
├── bin/                      # Build output (launcher scripts + binaries)
├── obj/                      # Object files and generated qrc/i18n files
└── plugins/                  # OneDrive storage plugin sources
```

## Conventions

- One `.cpp` in `lib/` and one matching `.hpp` in `include/` for each class.
- Test access shims are named `*TestAccess.cpp`/`hpp` and live next to the code they expose.
- Dialogs are `*Dialog.cpp`; services are `*Service.cpp`; managers are `*Manager.cpp`.
- UI strings are translated; use `tr()` or `UiTranslator` for user-facing text.
- All LLM and heavy work is driven from the main thread; progress dialogs are modal.

## Anti-Patterns

- See [../AGENTS.md](../AGENTS.md) for project-wide anti-patterns.
- **Do not add business logic directly to `MainApp` methods.** Prefer dedicated `*Service` classes.
- **Do not assume the active LLM is local.** Code paths that touch inference should work with both `LocalLLMClient` and remote clients.

## Notes

- `main.cpp` handles dev/test CLI flags (`--development`, `--test`, `--self-test`, `--updater-live-test`).
- The Linux launcher is generated by `app/scripts/gen_run_wrapper.py`.
- `resources/app.qrc` and generated `obj/translations.qrc` are compiled into the binary.
- Environment variables controlling runtime behavior are documented in `README.md` and `TROUBLESHOOTING.md`.
